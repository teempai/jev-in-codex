# Custom-policy expansion: prospective development protocol

Frozen before the first scored session, 2026-09-21. This admits or rejects the custom question/criteria interface as one workflow expansion; it cannot certify every future user taxonomy. The feedback preset remains a regression control. No new named presets are proposed.

Four fixed tasks: action-needed (2 labels), sentiment (3), document routing (5), and the existing feedback-theme preset (4). Each uses 64 records. New corpora are synthetic, authored with reference labels from templates before evaluation: 16 contexts with four variants each. IDs and row order do not encode the reference class. Templates share language and make distinctions deliberately explicit; this tests bulk delegation and artifact creation more strongly than subtle semantic generalization. Feedback data are the previously measured development corpus. No independent or real-world accuracy claim is planned.

Four repetitions per task per arm: 32 scheduled sessions, 256 distinct records, 1,024 decisions per arm counting repetitions. Alternate A/N order by repetition; reverse task order on odd repetitions. A is ordinary Codex with shell tools. N is identical Codex plus the shipped compiled MCP tool, instructed to call Jev and review uncertain evidence; source rereads and corrections remain allowed. Both receive the exact policy, input file and complete-output requirement. N has the additional custom policy schema and must pass the full criteria object through MCP. Same gpt-6-astra model, medium reasoning, priority service, no web/apps/other plugins/memory/global instructions. Jev pinned to jev-1.13.0. Use normal workspace-write with a session-scoped tool approval; no global changes.

Primary admission requires the existing POLICY.md gate **on each task separately**, including feedback regression: all final N outputs correct, no loss against A, actual successful Jev decisions on every N run; at least 20% lower paired geometric mean total Codex input or elapsed time, with the other no more than 10% worse. Overall aggregation cannot rescue a failing task. Complete artifacts, raw provider labels/confidence/usage, Codex usage/caching and failed commands retained. All scheduled failures remain in the primary calculation. An infrastructure failure stops the round, which remains failed/incomplete evidence; any later round must be disclosed. No adaptive repetitions, task deletion or outcome-based retries.

Record raw Jev mistakes and high-confidence errors, Codex repairs, full input/cache/output token categories and provider token counts. No monetary-cost or statistical-significance claim: technical repetitions measure run variation, not independent task diversity. Wall time includes MCP startup, review and artifact creation; process-global/network cache effects remain uncontrolled. Do not combine old and new runs as one experiment. A large-batch benefit must not be generalized to short input, all class counts, multiple simultaneous labels, modalities, high-stakes decisions or unspecified taxonomies.

Freeze source, compiled runtime, harness, fixtures, policy, reference labels and this protocol by SHA-256 before launching. Preserve this round even if it fails. Run `node benchmarks/run.mjs <new-output-directory> --custom`, then `node benchmarks/analyze.mjs <output-directory> --require-pass`. Publication removes only host-specific paths/session IDs and private runner configuration, retaining metrics and all substantive task/tool evidence. Validate the published copy by recomputing the same gate.

# Artifact workflow development experiment

This is a separate follow-up to the completed 20-case small-batch sweep, whose negative results remain unchanged. No positive effect is assumed. Two prospectively chosen workflows cover coding (API compatibility) and general work (customer-feedback themes). Each has 32 new authored records; none repeats an earlier fixture. Two repetitions per condition give eight sessions. These are development comparisons, not independent statistical confirmation or evidence about all twenty policies.

A uses plain Codex to produce decisions.jsonl. N uses the actual artifact-poc plugin to produce the same file with live Jev decisions, then reviews original records returned for confidence below 0.8. The threshold was chosen after the earlier development screen and is not claimed calibrated. Both may inspect any source record and correct the artifact. Both receive the identical complete policy inline in the task, removing a separate policy-file lookup from both conditions. Both may write the output file; neither may modify input records or take external actions. Ordinary tools remain unrestricted within that task boundary.

The entire output artifact is graded for exact ID coverage, allowed labels and reference-label correctness. Also retain raw Jev decisions, confidence, selected review set, edits and errors that escaped review. No compact summary can hide omitted or wrong records. The model, reasoning effort, service tier, clean configuration and alternating order match the previous screen. Wall time includes all startup, tool, file-writing, review and recovery work. Input/cached/uncached/output tokens and TypeSafe usage remain separate.

A promising development result requires no new incorrect decisions, all N records correct, actual Jev use, and at least 20% less paired geometric mean Codex input or elapsed time, with the other measure no more than 10% worse. Report both cases whether they pass or fail. No significance claim from two repeated batches. Freeze all plugin and harness files, fixtures, policy, answer keys and this protocol before scored sessions. Retain every run and all failures. A new runtime after these results would require a new disclosed development round.

The output is a local classification artifact only. No emails, payments, issue edits, code deployments or global instructions are changed. Production use would need larger held-out and representative evaluation, particularly for high-confidence mistakes that selective review might miss.
